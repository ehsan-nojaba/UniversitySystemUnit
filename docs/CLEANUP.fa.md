# گزارش تکمیل تمیزکاری

## هدف این مرحله

ساختار فایل‌ها و مسئولیت‌ها برای مطالعه و ارائه روشن شد. این مرحله اجرای تست کامل فرایندها و تکمیل دمو نیست.

## تغییرات معماری

- کوئری‌های EF بررسی درس مجاز و تداخل استاد به ریپازیتوری‌های Persistence منتقل شدند. قوانین تصمیم‌گیری در Application باقی ماندند.
- وابستگی مستقیم Application به EF و DbSet حذف شد. IApplicationDbContext در Persistence است و برای دسترسی داخلی داده و آماده‌سازی تست استفاده می‌شود.
- ریپازیتوری بررسی مجاز بودن درس، اطلاعات چارت و قبولی و پیش‌نیاز را دریافت می‌کند؛ حذف درس پاس‌شده و بررسی تکمیل پیش‌نیازها در سرویس Application انجام می‌شود.
- تداخل استاد یک سرویس مشترک دارد؛ ذخیره برنامه و تخصیص استاد هر دو از آن استفاده می‌کنند.
- ثبت‌نام، نتیجه دانشجو، گزارش و درخواست استاد به پوشه‌های مشخص DTOs، Services، Repositories، Commands و Queries تقسیم شدند.
- Handler مشترک چند عملیات استاد به Handler مستقل هر درخواست تبدیل شد.
- DTOهای چندکلاسه قدیمی، مدل‌های خروجی ریپازیتوری برنامه‌ریزی و DTOهای درس مجاز به فایل‌های مستقل منتقل شدند.
- قراردادهای HTTP از کنترلرها به Contracts و تبدیل JSON برنامه به Serialization منتقل شدند. مسیرهای HTTP و قالب درخواست‌ها حفظ شدند.
- AutoMapper و پروفایل خالی آن حذف شدند؛ هیچ نگاشت واقعی از آن استفاده نمی‌کرد و پاسخ‌ها به‌صورت صریح ساخته می‌شوند.
- زمان حسابرسی دیتابیس به UTC یکسان شد.

## توضیحات فارسی

مدل‌های دامنه، قراردادها، DTOها، سرویس‌ها، ریپازیتوری‌ها، Handlerها، Validatorها، کنترلرها و تنظیمات جدول‌ها Summary فارسی دارند. راهنمای اصلی سه فرایند و تفاوت اصطلاح‌ها را توضیح می‌دهد. نقشه کد مسئولیت هر کلاس و مسیر مطالعه آن را فهرست می‌کند.

## مرز بررسی

بیلد راه‌حل برای کنترل namespaceها، وابستگی‌ها و ثبت ساختاری تغییرات انجام می‌شود. در این مرحله تست جریان کامل اجرا نشده است. تست‌ها برای مرحله بعد آماده‌اند و دیتابیس موقت خودشان را دارند.

فایل‌های کانکشن، میگریشن‌ها و نگاشت ساختاری جدول‌های دیتابیس اصلی تغییر نکرده‌اند؛ تغییر فایل Configurationها صرفاً توضیحات فارسی است. میگریشن ایجاد یا اجرا نشده است. داده اصلی دیتابیس دستکاری نشده است.

## مرحله بعد

پس از تعیین کار بعدی توسط صاحب پروژه، می‌توان سناریوهای کامل، شکست‌های آموزشی و رفتار هم‌زمانی ثبت‌نام را بررسی کرد و دمو نهایی را آماده کرد.
