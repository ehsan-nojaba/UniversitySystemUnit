# نتیجه آماده‌سازی API برای UI

- API فهرست ترم‌ها، درس‌های فعال و استادهای دارای حساب فعال اضافه شد.
- API حساب جاری، نقش‌ها و پروفایل دانشجو یا استاد اضافه شد؛ رمز و هش رمز نمایش داده نمی‌شوند.
- CORS برای آدرس‌های محلی UI و تنظیم آدرس دلخواه فراهم شد.
- اشکال ذخیره وضعیت ارسال پیش‌انتخاب برطرف شد: Aggregate ارسال نهایی توسط EF رهگیری می‌شود.
- کوئری‌های خواندنی تا حد امکان در یک خط نوشته شدند؛ بلوک‌های دارای منطق و lambda چنددستوری چندخطی باقی ماندند.
- همه ifهای سورس و تست‌ها آکولاد دارند؛ این انتخاب در editorconfig هم ثبت شده است.
- راهنمای UI_API.fa.md نقش‌ها، مسیرها، بدنه‌های JSON، وضعیت‌ها، روز و ساعت و خطاها را توضیح می‌دهد.

## بررسی

بیلد: صفر خطا و هشدار. تست واحد: ۶۰ موفق. تست یکپارچه: ۴۰ موفق. سناریوی اصلی شامل ورود واقعی سه نقش، اطلاعات حساب، فهرست‌ها، ارسال دانشجو و استاد، ایجاد ارائه، تخصیص، برنامه، نتیجه، ثبت‌نام، رد تکرار و گزارش بررسی شد. CORS، حساب غیرفعال و تولید سند Scalar نیز بررسی شدند.

تست‌ها SQLite موقت دارند. این نتیجه تأیید رفتار هم‌زمانی SQL Server یا همه قواعد دانشگاه واقعی نیست. کانکشن، میگریشن و اسکیمای دیتابیس اصلی تغییر نکردند و داده اصلی دستکاری نشد.

تغییرات آماده کامیت صاحب پروژه هستند؛ کامیت در این مرحله توسط عامل انجام نشده است.

## قرارداد نوشتن کوئری‌ها

کوئری دارای Join با `from name in _context.TableName ... join ...` نوشته می‌شود. کوئری بدون Join با متدهای LINQ روی EF مانند Where، Select و FirstOrDefaultAsync نوشته می‌شود. هر دو قالب توسط EF به دیتابیس ارسال می‌شوند. کوئری‌ها تا حد امکان یک‌خطی و بدنه ifها دارای آکولاد است.
